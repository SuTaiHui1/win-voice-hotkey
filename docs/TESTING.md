# 验证范围：0.1.3

## 本版自动检查

`scripts/Test.ps1 -UnitOnly` 在专用不可见测试桌面运行1539项AHK输入/设置回归与21项状态快照检查，并运行8项C#面板核心纯检查。测试不会切换用户桌面、发送Win+H、访问麦克风或调用真实UIA关闭。单次真实成绩以CI产物的 `out/tests-*/results.json` 为准。

状态检查覆盖旧PID替换、主程序与代理完整就绪条件、原子快照与临时文件清理、状态缺失/被替换后的重发、正常/失败退出、伪成功写入、错误读回和锁定导致的替换失败。合成错误是测试输入，不是对本轮自然登录故障的归因。

同一命令还运行13项无输入生命周期回归：分离无控制台/标准句柄的启动、实际PID、重复启动保持身份、无效令牌拒绝、旧PID定位真实实例并正常停止、终止状态、初始化失败非零、后续成功启动、默认日志、配置保持与无残留。它使用独立目录和唯一测试互斥锁，不安装钩子，也不停止日常程序。

设置检查覆盖Esc出口、录制边界、暂停/取消/保存、回滚、滚轮手势及隐藏GUI的布局矩形。矩形检查不是受支持截图或最终视觉验收。不同字体、DPI和显示器仍需人工验证。

发行包在独立目录做静默隔离安装、无输入冒烟与卸载；冒烟覆盖代理就绪、设置打开/关闭、隔离自启入口往返、停止状态与配置/无关文件保留。默认绑定仍为XButton1/XButton2，不包含任何人的个人配置。

## 单机真实登录证据与更正

在一台Windows 11 x64主机上，完整内核重启、自然登录后，已核实新实例的启动/主初始化/代理就绪日志、实际状态快照、进程和实例身份；内部代理握手及键盘/鼠标钩子均已建立。此后一次正常退出和正常启动也记录了相应状态。后一次手动启动不替代前一次自然登录证据。

此前0.1.2文档将“登录后看到旧PID/Running=0”列为已知问题。后续直接证据确认：检查进程打开同样路径文字时，实际读取的是打包应用私有缓存里的旧副本；自然登录实例读写真实用户Roaming目录，其新状态和启动日志已存在。已更正该检查结论，不能把缓存误读继续当作产品缺陷，也不能据此追认更早的INI/系统缓存故障推测。相同路径文字、高完整性或UAC虚拟化关闭都不足以证明读取了同一物理文件。

检查工具可能受打包应用文件视图影响，必要时核对已打开句柄的最终路径。微软文档说明了[打包桌面应用的AppData合并/重定向行为](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)。原始配置、机器路径、PID、日志及私有诊断证据不公开分发。

0.1.3与已验证日常版本的业务逻辑一致，发布版本号/构建标记有更新。发布工作不停止或升级现用实例、不改其个人绑定或自启；发行包的隔离检查不是新的物理键鼠或自然登录验收。

## 历史基线与未验证

历史单机交互覆盖右Shift同键开关、XButton2真实CloseButton.Invoke和手动X后重开；录音中关闭有旧版本接受记录，未作为本版专项重测。此前隔离环境32项退出/安装和93项停止门禁为历史基线，本轮未启用Sandbox重跑，不移除脚本的隔离保护。

尚未验证所有物理键鼠/驱动、全部录音状态、长期稳定性、Windows 10、ARM64、更多Windows 11构建、远程桌面、管理员应用、受保护桌面、各DPI/显示器、全新虚拟机及最终视觉。没有再次重启主机来验证发行版本元数据更新后的自然登录。

这些结果不是跨设备兼容保证、代码签名、安全审计或固定延迟承诺。
