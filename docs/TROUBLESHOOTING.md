# 故障排查（0.1.4）

## 没有弹通知，也没出现语音面板

中文保障的成功、准备、失败、取消全部静默，不会主动弹窗。这不是把失败改成成功。手动打开托盘“查看状态”，或查看自己的数据目录中的mapping-state.ini及lifecycle.log。

先在独立空白文本框手动按Win+H，区分系统语音输入条件和本工具的绑定/语言准备问题。确认程序托盘存在、设置窗口关闭、光标确实在编辑控件、没有其他工具占用同一键。重新聚焦后再按，不反复连按。

## 中文输入语言没有确认

| LanguageResult | 含义与下一步 |
| --- | --- |
| ready | 原目标的简体中文已确认并交给唤醒路径；不保证面板完整出现或识别成功 |
| switching | 正在等待目标输入线程确认中文；期间不要切焦点/语言 |
| missing_chinese | 当前可用布局里未找到zh-CN；在Windows中核实简体中文输入法，本工具不自动安装 |
| no_target | 没有可靠的目标编辑窗口；将光标放到独立文本框后重试 |
| focus_changed | 原窗口或焦点变了，本次已取消；新焦点不会被抢回 |
| user_language_changed | 准备期间用户改变语言，本次取消；选择好目标后重新触发 |
| switch_request_failed / switch_timeout | 目标拒绝或未确认切换；尝试普通非管理员文本框，检查系统输入法和Win+H |
| cancelled | 同键/关闭操作等取消了尚未发送的打开 |

系统提示“语音键入不可用于当前语言”时，先核对是否直接手动按了Win+H，或目标控件不支持所需语言切换。本程序只在能确认原目标zh-CN后发送；不保证所有TSF控件、管理员窗口和远程桌面兼容。关闭后不自动恢复旧英文，用户可以自己Win+空格切换。Windows的原生错误面板仍由Windows显示，本工具不全局屏蔽它。

## 找不到代理进程

`BrokerMode=on_demand`、`BrokerPhase=idle`、`CloseBrokerPID=0`、`CloseBrokerReady=0`且主程序Ready=1是正常待机。需要请求时才启动代理；面板不存在且无活动操作持续空闲约10秒后回收。代理存活时仍加载.NET/UIA组件，不能用待机17MB估计实际听写系统总占用。

`starting`表示冷启动，`busy`表示在途查询，`stopping`表示空闲正常退出；这些期间请求有界处理，不应手动启动VoicePanelBroker.exe。`failed`及BrokerLastError表示真实故障；检查lifecycle.log，下次操作可尝试恢复，程序不会后台无限重启代理。持续失败时先托盘退出，再正常启动本程序。

Ready=1表示主程序能接收请求，不等于正在录音；CloseResult为上次面板请求结果，可能与独立的语言准备结果不同。不要只看一个字段判断成功。

## 能打开但不能关闭

关闭需识别唯一真实语音面板及可用CloseButton.Invoke；目标不确定、控件没准备好或超时就停止，不会用坐标点击/Alt+F4兜底，也不会结束系统服务。可手动点击系统面板X，再重新触发。记录CloseResult、BrokerLastError和Windows版本，但不要附听写草稿。

## 升级或卸载中止

安装器先验证并停止本安装的实际实例。`--stop`返回2表示验证/终态未确认，3表示超时。先托盘正常退出后重试，确认安装目录有本项目标记；不要因文件同名就强行结束其他AutoHotkey程序。无标记的非空目录不会被当成可覆盖安装。

## 状态与实际程序不一致

核实数据来自当前安装模式、同一用户和实际物理目录。部分打包宿主或检查环境可能看到同名AppData缓存副本；同名路径或进程存在本身都不足以证明状态正确。安装版使用 `%APPDATA%\WinVoiceHotkey`，便携版使用本目录data。检查PID对应的程序路径、窗口/实例令牌与最近日志，不能拿旧副本当当前状态，也不要修改状态来伪造就绪。

## 提交问题前

说明版本、Windows版本、安装/便携模式、绑定以及可重复步骤。可摘录已脱敏的LanguageResult、BrokerPhase、BrokerLastError、CloseResult和生命周期错误。不要上传整个AppData、个人配置、原始诊断包、完整机器路径、草稿或音频。可选支持日志默认关闭，详见[隐私说明](PRIVACY.md)。
